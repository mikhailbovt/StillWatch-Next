# StillWatch Next acceptance evidence

The evidence below follows §23.1 of the Russian technical plan and the [completion plan](../StillWatch_Next_Completion_Plan_RU.md). The [Fast RC v2 contract](../qualification/README.md) governs new native qualification and lists the 17 release requirements and G1–G5. Earlier measurements apply to their original builds and workload. `IMPLEMENTATION_STATUS.md` records dated results and open checks. Several acceptance criteria still require a different host, physical equipment, release credentials, or additional data.

An Ubuntu 24.04.4 VM running the packaged Core was killed at the QEMU process after an incident and JPEG were readable through the API. On a second boot, the service recovered the original Core identity and incident, and the same evidence bytes were available. SQLite integrity and foreign keys passed, replay created no delivery, and capture and inference resumed on a new source epoch. Physical-device power loss and interruptions at other transaction boundaries remain open.

`tests/e2e/model_activation.py` verified square and rectangular CPU packs on Windows and Ubuntu. The worker checked all graphs before creating sessions, qualified both packs on the reference fixtures, and published a new model selection atomically. Failed validation preserved the previous selection. Running workers kept the previous pack until the Core restarted. Incidents retained their original model and policy identifiers across the change and rollback.

`tests/e2e/analysis_core.py --source-freeze --media-encoder PATH` verified an uninterrupted RTSP feed with increasing timestamps on Windows and Ubuntu. Repeated decoded frames made the source unavailable, hid current observations and suspended JPEGs. Moving frames restored inference with a fresh source epoch. The Linux Companion from the DEB cleared its preview, indicated repeated frames in the grid and in the full viewer, and automatically resumed masked WHEP. The Android 16 release APK fell back to fresh masked JPEGs during packet loss and restored WHEP after reconnecting.

Schema 8 persists technical health intervals separately from the hazard and notification queues. Windows and Ubuntu observed RTSP freeze, recovery, disconnection and an invalid model hash, then confirmed the intervals after restarting Core. Ubuntu also tested an inference timeout, process termination and a data-volume free-space change from below to above the threshold. With an offline Firebase fixture, route unavailability and budget exhaustion could coexist and end independently. All four SDKs tested camera scoping and pagination through TLS. The Linux Companion DEB showed active and ended events with timestamps and filtered active events. A clock-step unit test used synthetic UTC and monotonic readings. The separate alarm monitor remains the source of evidence for an unreachable Core.

The schema-7 Windows and Ubuntu binaries created a database and offline backup. Schema 8 preserved the Core ID, the configured camera and a prior incident. The schema-7 CLI refused the upgraded database and opened a restored schema-7 copy. The schema-8 CLI restored the same backup into an upgraded directory. This used the native binaries and disposable data directories. The legacy source import also passed on both platforms.

The 2,105-incident fixture exercised a limited open snapshot, all pages of history, acknowledgement of an older incident, and delivery to a new SSE subscriber on Windows and Ubuntu. The four-camera mixed Ubuntu run included one active RTSP feed, three replays, two concurrent WHEP clients per round, device session refresh and two deliberate Node worker outages. The short run lasted 720 seconds. No source had cloud consent during this test.

The Android 16 emulator preserved the observed notification denial time after force-stop and cleared it immediately after returning from the system permission screen. iPhone 17 Pro Simulator verified pinned TLS, masked WHEP, profile retrieval from Keychain, and the health journal. The test confirmed the incident in the iOS notification center under provisional authorization and a Core receipt with ACK still unset. The same run produced an unsigned iOS archive. [iOS qualification](https://github.com/mikhailbovt/stillwatch-next-ios-qualification/actions/runs/43547081335)

`tests/e2e/rtsp_core.py --dpapi` verified TCP and UDP camera access with a machine-protected Windows secret, recovery after publisher restart, and rejection of a corrupt protected blob even when a valid JSON copy existed. The MSI installed in an offline Server 2025 guest decoded authenticated RTSP frames under LocalService using a DPAPI blob created by the administrator. Windows and Ubuntu also passed the established JSON reference path.

`core_diagnostics.py` verified removal of abandoned MediaMTX configurations even with media disabled. `whep_core.py` verified hashed loopback credentials, isolation from inherited MediaMTX overrides, and two masked H.264 streams on Windows and Ubuntu. The Ubuntu run used an HEVC source and Coturn with relay-only ICE over TLS. The router file contained no TURN signing secret. [MediaMTX configuration](https://mediamtx.org/docs/features/configuration)

On Ubuntu, `whep_core.py --crash-restart` killed the foreground Core after live negotiation and verified exit of its direct children. The next Core bound the same ICE port, removed the abandoned router configuration and started the stored camera with a new source epoch. A separate run with active ONNX inference also confirmed exit of all three direct children. [Linux parent-death signals](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

`whep_core.py --mask-change` changed a mask while a viewer was connected. The previous WHEP session became unavailable and the replacement session showed the new mask in decoded pixels. Windows used direct ICE on a private interface. Ubuntu used an HEVC input, H.264 playback and Coturn TLS.

`analysis_core.py --camera-sampling` exercised per-camera pose, fire and evidence rates through the API on Windows and Ubuntu. It rejected an out-of-range setting, measured the lower inference cadence, checked persisted evidence coverage and restored the defaults after restarting the Core and reloading the saved configuration.

The same test verified camera priority persistence on Windows and Ubuntu. Deterministic jobs test aging past the priority bonus, selection of overdue fire work, and source-time spacing and cooldown for extra fire work. Analysis status reports cadence deficits by camera.

The iOS workflow retains the unsigned arm64 device archive, its SHA-256 checksum and source commit. The WSL test used a disposable certificate on the same bundle and verified the Mach-O signatures of Runner, Flutter AOT, Flutter, WebRTC and Objective-C before checking the IPA archive. xtool's unsigned validation passed with the expected provisioning warning after replacing the default Flutter assets. Apple-issued device signing and installation remain open.

`replay_core.py` and `rtsp_core.py` observed the decoded H.264 codec in the probe and camera runtime on Windows and Ubuntu. At the four-camera limit a new source failed preflight while an edit fit using its own reservation. Two drafts each passed preflight for one vacant slot, then only one concurrent save committed. A raw-frame limit smaller than one frame still returned the estimate and rejected activation. The Companion widget test verified that the save waits for confirmation when capture resources are available.

`whep_core.py --dual-rtsp --mask-change` checked two viewers on one detail decoder on Windows via direct ICE and Ubuntu via Coturn TLS. Preview and snapshots came from the 320×240 analysis stream. Both detail viewers decoded masked H.264 at 640×480. The test changed the privacy mask, closed the last viewer, interrupted and restarted the detail source, and verified that capture and ONNX pose and fire counters advanced in the same analysis epoch during the interruption. The probe rejected an invalid or repeated path and incompatible masked geometry. `--detail-budget-test` checked that a rejected detail offer leaves the analysis preview available. Physical dual-profile cameras and inference cadence under concurrent high-resolution viewing remain open.

`tests/e2e/storage_budget.py` verified SQLite metadata exhaustion and backpressure on the WAL with an external reader on Windows and Ubuntu. The API kept committed state readable, returned 507 for blocked writes, and accepted a retry after headroom returned. The maintenance CLI produced a redacted report while readiness returned 503. A storage test restarted with pending evidence in a full database and completed reconciliation after freeing pages.

The backup and restore CLI rejected a small byte budget on both systems and insufficient destination headroom on a 48 MiB Ubuntu tmpfs. Failed operations left no published directory. A subsequent restore preserved the incident and camera and changed the stream generation. The CPU Compose profile verified its mounted temporary filesystem size and the driver settings for log rotation.

The KMU replay added one low-light smoke onset, one daytime clip with smoke present at the start and ten labeled lookalikes. Neither positive matched the eight-second window. The low-light sequence ended 5.33 seconds after the labeled onset. The daytime clip produced a review at 13.67 seconds, and five lookalike clips produced 13 fire reviews. See `models/evaluations/kmu-fire-smoke-v1.md` for scope and hashes.
