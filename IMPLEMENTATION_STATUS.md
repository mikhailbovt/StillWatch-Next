# StillWatch Next 0.1.0

StillWatch Core автономно анализирует камеры и хранит события локально. Companion собран для Windows, Linux, Android и iOS. Продукт использует закреплённые веса. Ранний огонь, дым и падения могут быть пропущены или обнаружены с задержкой. [Ограничения](LIMITATIONS.md)

## Core

- Core сразу сохраняет инцидент в SQLite. При согласии камеры, доступном Firebase и свободном бюджете он проверяет пакет открытия один раз. Ожидание первого Review ограничено десятью секундами. При недоступности облака действует локальный путь. Проверены один запрос к Gemini в выпускном проекте, пропуск камеры без согласия и сохранение просроченного ответа в журнале. [Настройка Firebase](docs/firebase-worker.md)
- 26 ноября проверен пересмотр одиночного локального Fire Review. Ответ Firebase с видимой альтернативной причиной и несколькими согласующимися изображениями переводит ожидающий Review в Info. Пакет остаётся в истории. Узкие Rust-регрессии проверили снятие отложенного уведомления, запоздалый ответ и возврат к Review на новом наблюдении. Проверка также принимает отчёт о пламени у видимого контролируемого источника при отсутствии дыма и распространения. Реальный Gemini в выпускном проекте распознал синтетическое изображение на экране как источник ложного сигнала. Эта проверка не измеряет качество на частных записях или новых площадках.
- Нативные release-тесты Core, API, хранилища и движка дали 69 успешных проверок на Windows и 71 на Linux. На каждой платформе одна проверка осталась пропущенной. На Windows проверены RTSP TCP и UDP, переподключение, два WHEP-сеанса с маской и ротация доступа к трансляции.
- Windows CPU4 прошёл 120 секунд после прогрева из чистого пакета на общем хосте. Минимумы за минуту источника составили 294 Pose и 120 Fire. Декодированы 8 из 8 JPEG и 600 кадров WHEP. Зафиксировано одно контрольное открытие, пропусков и остановок зрителя за этот интервал не было. Полный результат остался INCOMPLETE из-за сокращённого прогона и общего хоста. Linux CUDA16 ранее отработал такой же интервал с минимумом 294 Pose и 114 Fire, 16 из 16 JPEG и пиком VRAM 4,77 ГиБ при лимите 8 ГиБ. Изолированная квалификация остаётся открытой. [Профили приёмки](qualification/README.md)
- Windows и Linux проверили захват с физической USB-вебкамеры. Linux UVC проверен в Ubuntu WSL2. ONVIF прошёл серверный стенд. WHEP и TURN проверены на локальном стенде и с двумя зрителями. Физический ONVIF и две независимые сети остаются за пределами этих результатов.

## Хранение и обновление

Core из Windows MSI обновил нативную базу 17 → 18. После обновления те же настройки, инцидент и четыре JPEG читались через API. Контрольные суммы изображений совпали. Прошли новая запись, перезапуск, восстановление Windows-копии в Linux CPU и возврат к схеме 17 из исходной резервной копии. [Восстановление и откат](docs/operations.md)

## Демо и бета

- На выпускном Linux Core проверены закрепление TLS, одноразовое зачисление устройства, изоляция камер по роли viewer, ротация refresh-токенов и отзыв доступа. [Подключение тестера](docs/demo-access.md)
- В выпускной сборке подтверждены результаты Firebase AI Logic `on_device` и `in_cloud`. В шестисекундном интервале отключения браузерного worker Core принял ещё 31 наблюдение Pose и 12 Fire на RTSP. Для cloud-ветки проверена отдельная камера без согласия. [Воспроизводимая процедура](docs/hybrid-review.md)

- Linux Companion показал два RTSP-источника, маскированный WebRTC и реальные Review на тестовом огне и инсценированном падении. Подписанный Android APK прошёл подключение и подтверждение Fire Review. На Android 16 отдельно проверены системное уведомление, запись квитанции Core и открытие Companion из уведомления на контрольном Urgent.
- iOS 0.1.0 (4) доступна во внутренней группе. Статус внешней сборки READY_FOR_BETA_SUBMISSION. Публичная ссылка зависит от Beta App Review и доступного демо-Core.

## Качество и распространение

- Эксперименты с Fire и классификатором падений завершены. Сравнение обнаружило поздние или пропущенные сигналы, ложные Review и дубли. Сохранены текущие веса и правила. Независимая оценка по новым площадкам, людям и редким ложным тревогам относится к следующему обновлению. Автономный Urgent требует собственной проверки. [Критерии качества](qualification/quality-contract.json)
- Три ONNX-файла сверены с lock-файлом внутри Windows MSI и Linux CPU/CUDA DEB и RPM. Публичному распространению пакетов с весами предшествует решение по условиям AGPL и исходным материалам Fire. Текущие MSI без Authenticode. [Хеши и лицензии моделей](models/THIRD_PARTY_NOTICES.md)
- Чистая установка CPU теперь получает ONNX Runtime 1.31.0 из закреплённого пакета Microsoft на NuGet. Windows DLL и Linux SO совпали по SHA-256 с выпускными файлами. Нативный doctor открыл все три модели на обоих хостах.
- История измерений и планы разработки сохранены в локальном архиве. Текущие проверки и условия приёмки приведены в [матрице](docs/acceptance.md).
